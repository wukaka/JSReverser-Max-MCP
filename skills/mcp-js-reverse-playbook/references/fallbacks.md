# 失败回退
- Hook 无数据：确认动作执行 -> 扩一档范围 -> 仍失败则停，不要直接猜 local rebuild。
- 如果 Hook 错过首屏初始化：回到页面入口，先补 `inject_preload_script` 再重试。
- 数据过多：summary 去噪 -> raw 单条下钻。
- 本地补环境失败：先读代理 env log，确认当前 `first divergence`，再回看页面证据；`diff_env_requirements` 仅作辅助。
- local rebuild 连续两轮无进展：回到页面观察，补 `record_reverse_evidence` 后再继续。
- 断点不稳：回退 Hook 路径。
- 输出长度或签名上下文不匹配：先在真实客户端内做消融/替换，确认参数是否被校验；不要继续补环境。
- 数字字段不一致：先做稳定性分类（同进程 / 跨进程 / 不同输入），再决定是否补。
- 输出不可读：先判定是序列化、编码、压缩还是加密，再按实际变换路径解码；不要直接假设为加密。
- 重放被拒：先确认是重放检测而非内容拒绝，再改用样本库 + 新鲜请求。
- 以上都无进展：检查会话物料是否同源（成对签发的材料是否来自同一次签发、是否有预置派生值）。

## Hybrid Fallback

当纯离线卡在无法解释的内部状态（如字节码虚拟机）时，允许降级为 hybrid：由真实客户端完成签发或生成，离线部分负责组装与提交。

报告必须明确区分：

- hybrid 跑通：证明服务端接受该组装方式；
- 纯离线跑通：证明生成链路可脱离客户端。

两者不能互相代替。
