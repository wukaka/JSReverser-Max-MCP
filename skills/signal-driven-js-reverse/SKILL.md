# Signal-Driven JS Reverse Engineering

## 1. 定位

本 skill 不重复两个配套 skill 的规则正文，只负责编排。

| 层 | skill | 职责 |
|---|---|---|
| 决策层 | `blackbox-js-reverse-engineering` | 测什么、怎么设计实验、怎么判定证据与根因 |
| 执行层 | `mcp-js-reverse-playbook` | 用什么工具观察、篡改、取证、重建 |
| 编排层 | 本 skill | 阶段门、链路范围、账本、止损与升级 |

任务开始时同时加载两个配套 skill；本 skill 决定何时进入哪一阶段、何时停、结论怎么写。

## 2. 核心原则

- **Signal over motion**：每一轮必须减少不确定性；没有信息增益的动作立即停止。
- **One chain at a time**：每条结论标注适用链路（browser / local rebuild / hybrid）；一条链路的结论不外推。
- **Gate before rebuild**：未判定服务端实际检查什么，不开始补环境。
- **Evidence or it did not happen**：未提交给目标的输出不是证据；未复现的结论不是事实。
- **Negative results are assets**：证伪与撤回必须入账，不覆盖。

## 3. 阶段与门

### G0 Frame

产出：

- 目标接口与字段
- 提交路径与验收标准
- 链路范围（browser / local rebuild / hybrid）

退出条件：能用一句话说明“什么算成功”。

### G1 Observe & Capture

用 playbook 的 Observe / Capture 取证；用 blackbox Phase A 建基线。

产出：

- 目标请求、脚本与候选函数线索
- 参数样例、调用顺序
- task artifact
- 响应码语义表（含“重放拒绝”单列一类）

门：至少有一条真实提交记录；错误码已分类。

### G2 Isolate（硬门）

先做重放检查：

- 重放通过 → 作为正控制；
- 重放被拒 → 先分类；确认是重放检测后，改为建立多次成功通过的参数样本库（跨时间/会话），后续实验一律使用新鲜请求。

然后在可信客户端内做篡改/消融，判定服务端实际检查的层与字段。

退出条件：

- 能明确说出当前失败属于传输 / 客户端上下文 / 内容 / 时间 / 会话状态中的哪一层（开放式分类）
- 后续补环境只针对该层

未过此门，禁止进入 G4。

### G3 Hypothesize

用 blackbox Phase C：至少两个竞争假设、单变量、先写预测与证伪条件。

退出条件：下一个实验能区分至少两个假设。

### G4 Rebuild & Patch

只针对 G2 判定的层补；一次一个最小因果单元；每轮复测 `first divergence` 是否前移。

约束（细节见 playbook）：

- 成对物料同源，禁止跨会话拼接
- 不预置 SDK 会自行派生的值
- 禁止空 catch

退出条件：目标参数稳定生成，且 `first divergence` 不再前移。

### G5 Validate

用 blackbox Phase F：在原定链路做端到端验证，分离已证明与未解决。

退出条件：结果可按链路陈述；回归检查完成。

### G6 DeepDive（可选）

去混淆、VMP、控制流还原。仅在需要长期复用或仍有不可解释行为时进入。

## 4. 证据账本

单一账本，追加式编号，不覆盖旧结论：

- 每条标注 OBSERVED / INFERRED / SPECULATIVE / VERIFIED
- 每条附：日期或轮次、适用链路、复现命令或脚本路径
- “已证伪 / 已撤回”单独成表
- 静态提取结果与运行时验证真值分文件存放

## 5. 升级与回退

- **连续两轮无信息增益**：停止打补丁，回页面取证或重新分层。
- **纯离线卡在不可解释的内部状态**：可降级 hybrid；报告必须分链标注，hybrid 跑通 ≠ 纯离线跑通。
- **输出长度或上下文不匹配**：先做稳定性分类与输出变换判定，不补环境。
- **重放被拒**：先确认是重放检测，再切换样本库 + 新鲜请求。
- **多路径结论冲突**：用根因三条件裁决；只修通一条链路的记为路径级阻塞。

## 6. 止损条件

满足任一即停止当前方向：

- 已达验收标准且有可复现证据；
- 剩余不确定性已明确记录，且下一个实验的信息增益低；
- 连续两轮无信息增益，且没有新的竞争假设。

## 7. 报告格式

1. 结论（按链路分别陈述）
2. 已确认事实
3. 根因或领先假设 + 置信度
4. 关键实验与结果
5. 改动与验证
6. 未解决项
7. 下一个最高信息量实验
8. task artifact 路径

## 8. 反模式

- 跳过 G2 直接 Rebuild，产生大量与闸门无关的环境补丁
- 把一条链路的阻塞当成根因
- 以输出长度或表面相似度为目标
- 跨会话拼接物料，或预置派生值
- 静默 catch 吞掉解密/解析失败
- 在重放检测环境下用旧样本做跨客户端比较
- 无预测的实验、无账本的结论
